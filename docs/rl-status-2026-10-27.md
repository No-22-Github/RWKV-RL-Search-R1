# Search-R1 RL 状态报告

日期：2026-10-27 ｜ 覆盖：v3b 结案 → 检索配置矩阵（BM25 / e5 重排 / e5 Flat）→ 上游协议对齐 → v4 就绪

## TL;DR

- **v3b 结案：难题池 100 步对 held-out 净贡献为噪声级**（s250 0.3975 → s300 0.3956），题池侧「二刷零增益」坐实，停训正确。
- **本轮最大收益来自检索，不是训练**：同一 s300 权重，把检索从裸 BM25 top-3 换成 **e5 Flat 语义检索 top-5，EM@1 从 0.3956 → 0.4769（+8.1 点）**，all-time 最高。分数据集 NQ 0.4913 / HotpotQA 0.4625（后者 +3.0 创多跳题新高）。
- **已超过 Search-R1 论文里 Qwen2.5-7B-Base PPO 的两集数字**（NQ 0.480 / Hotpot 0.433），口径差异见「上游对齐」一节；七集平均尚未跑。
- **e5 检索基建完成并 GPU 化**：64.6GB Flat 索引 + torch fp16 后端（0.8ms/query，2101 万段落精确检索），8002 服务可直接喂 v4 训练。
- **v4 检索配置定稿**：flat e5 + top-5；训练起点 s300；待办 = 新二进制冒烟（内存测量）+ 在新检索环境下重筛题池。

## 评测口径

held-out：200 题（NQ 100 + HotpotQA 100）× 8 采样，T0.3 / top_p 0.5 / max_turns 4，**检索配置为本轮新增变量**：

| 检索配置 | 说明 |
|---|---|
| 裸 BM25 top-k | pyserini + wiki-18 Lucene 索引（历史基线口径） |
| e5 重排 top-k | BM25 召回 top-50 → e5-base-v2 语义重排（词面池内精排） |
| e5 Flat top-k | intfloat/e5-base-v2 + 官方预建 FAISS Flat 索引（2101.5 万段落，语义召回完全体） |

EM@1 / pass@8 / 宽松 pass@8 / 全错题 / avg_search 定义同上一份报告，评测噪声 ±0.02。

## 一、训练侧：v3b 结案

v3b（s200 起、多跳偏好难题池）训练窗口与 held-out：

| 检查点 | EM@1 | pass@8 | 宽松 | 全错题 | 备注 |
|---|---|---|---|---|---|
| v3b-s250（难题池 50 步） | 0.3975 | 0.455 | 0.480 | 109 | 名义峰值 |
| v3b-s300（难题池 100 步） | 0.3956 | 0.440 | 0.485 | 112 | 打平，净贡献 ≈ +1.5（噪声级） |

判死依据（训练侧窗口）：

- **二刷零增益**：题池 ~1450 题 ÷ 16 题/步 ≈ 91 步/epoch，100-109 步窗口全是二刷题，acc 0.484 ≈ 首刷水平；对照 v2 同期同题二刷 +8.8 点——**连背题都没背进去**；
- 行为期假设证伪：搜索 2.61 → 2.38 净下滑，109 步内没有 v2 的「搜索爬升 + acc 破平台」签名；
- 题池众数为 1/8 对的题，成功轨迹过稀，组内梯度推不动——难题池的物理代价。

## 二、检索侧：六配置矩阵（同一 s300 权重）

| 检索配置 | EM@1 | pass@8 | 宽松 | 全错题 | avg_search |
|---|---|---|---|---|---|
| 裸 BM25 · top-3 | 0.3956 | 0.440 | 0.485 | 112 | 2.15 |
| 裸 BM25 · top-5 | 0.4475 | 0.495 | 0.525 | 101 | 2.09 |
| 裸 BM25 · top-7 | 0.4394 | 0.480 | 0.525 | 104 | 1.96 |
| e5 重排 · top-3 | 0.4550 | 0.490 | 0.530 | 102 | 2.06 |
| e5 重排 · top-5 | 0.4431 | 0.475 | 0.515 | 105 | 1.95 |
| e5 Flat · top-3 | 0.4444 | 0.475 | 0.510 | 105 | 2.01 |
| **e5 Flat · top-5 ★** | **0.4769** | **0.500** | **0.540** | **100** | 1.94 |

配对分析（1600 轨迹）：

- flat_t5 vs flat_t3：**+3.25**（解锁 10 题 / 丢 5 题）——完整语义召回下，第 4-5 篇不再是干扰项而是 BM25 召不回的真正相关文档；
- flat_t5 vs 重排_t3：+2.19（解锁 15 / 丢 13）；
- flat_t3 vs 重排_t3：−1.1，噪声级（top-3 下「更好召回」与「更好精排」互相抵消）。

### 关键机制发现

1. **窗口最优取决于召回质量**：裸 BM25 最优 top-5（top-7 掉）；重排（词面池内）最优 top-3（top-5 掉）；**完整语义召回最优 top-5**——检索池质量决定了多给的槽位是信息还是噪声。
2. **训练收益 × 检索配置有交互**：top-5 相对 top-3 的增量随训练变强——v1-s100 **+0.1**、v2-s200 **+1.9**、v3b-s300 **+5.2**。难题池练出的「多文档提取拼接」能力在 top-3 下施展不开、top-5 下兑现；v3b 在旧口径下看着无用，换检索后价值显形。
3. **答案位置分布**（200 题首查 query 重放）：第 1-3 篇 40% / 第 4-5 篇 8% / 第 6-8 篇 4% / **前 8 篇都没有 48%**。前两者解释 topk5 的红利，最后那个 48% 桶是语义召回的靶子——Flat 上线后 HotpotQA +3.0 即为兑现证据（桥接文档被语义召回救回）。

## 三、e5 检索基建（本轮工程主体）

- **模型/索引**：`intfloat/e5-base-v2`；官方预建 Flat FAISS 索引（HF `PeterJinGo/wiki-18-e5-index`，64,559,075,373 字节，两个分片 `part_aa` 40GiB + `part_ab` 20.1GiB，sha256 见记忆）；语料复用现有 `data/retrieval/wiki-18-store`（docid=行号，自检通过）。
- **服务**：`retriever/e5_server.py`，`POST /retrieve`，端口 8002。两种后端：
  - `--backend faiss`：faiss-cpu 全库扫描（兜底；**该 Blackwell 卡上 faiss-gpu 无 kernel，CUDA error 209**）；
  - `--backend torch`：从 faiss 文件零拷贝取向量 → GPU fp16（32.3GB 显存）→ 分块矩阵乘精确检索，**0.8ms/query**，是生产配置；
- `retriever/e5_rerank_server.py`：BM25 top-50 → e5 重排（探针用，端口 8001）。
- **部署坑清单（已全部解决）**：
  1. `cat part_aa part_ab > index` 写进自动链时，若分片缺失，重定向会先把目标截断为 0 字节 → 拼装前必须校验分片 sha256/大小；
  2. faiss `IO_FLAG_MMAP` 读该索引报 `read error`，且 `index_cpu_to_all_gpus` 在 cu12 轮子上 SWIG 报 TypeError、fp16 大分配 OOM、Blackwell 无 kernel——**统一用 torch 后端绕过**；
  3. `uv run` 会按 lockfile 把 torch 回滚成 `+cpu` 版；服务端一律 `.venv/bin/python` 直跑；
  4. pyserini 导入时会联网拉清单（超时挂起）、transformers `from_pretrained` 在线检查也会挂起 → e5_server 内联 CorpusStore + `local_files_only=True`，零网络依赖；
  5. Mac 侧 `requests` 会读取 `http_proxy` 把 tailnet 请求塞进代理（1600-query 大响应 600s 超时）→ 评测客户端 `trust_env=False` 永久修复；检索请求改 512 分块 + 1200s 超时；
  6. 重排服务曾因「个别 query BM25 零命中」触发 `np.stack` 崩溃 → 空结果直接返回 `[]`。

## 四、上游协议对齐（Search-R1, PeterGriffinJin/Search-R1）

从代码挖出的评测协议（论文未写全的部分）：

- **解码**：贪心（`do_sample=False`）、每题 1 次、无 temperature/top_p（`verl/trainer/ppo/ray_trainer.py::_validate`）；
- **检索**：e5 exact（Flat）over wiki-18，top-3（`GenerationConfig.topk=3`）；每篇 ~200 token，observation 截断 500；单轮回复上限 500，总长 4096；B=4 轮，**最后一轮强制只答不搜**；
- **题库**：`scripts/data_process/qa_search_test_merge.py` 从 `RUC-NLPIR/FlashRAG_datasets` 取 **全量** split（test→dev→train 回退），七集：NQ / HotpotQA / TriviaQA / PopQA / 2WikiMultiHopQA / MuSiQue / Bamboogle；
- **EM**：取最后一个 `<answer>`，归一化 = 小写→去标点→去冠词→空白归一，**与我们 `eval_base.normalize_answer` 逐行等价**；per-dataset 均值 → 七集平均。

对齐现状（1:1 可比还差什么）：

| 环节 | 状态 |
|---|---|
| EM 归一化 | ✅ 代码级一致 |
| 题库 | ⚠️ 目前 200 题抽样；需换全量七集 |
| 检索 | ✅ flat e5 已上线；正式口径用 top-3 |
| 解码 | ❌ 需加 `--greedy` 单次模式 |
| 轮次/长度 | ❌ 需加末轮禁搜 + 500/500/4096 截断 |
| Agent 格式 | ⚠️ 不可对齐（本模型原生 G1K `<tool_call>`），脚注注明 |

位置参照：Qwen2.5-3B 档七集平均 0.303–0.389（含更易的 TriviaQA）；Qwen2.5-7B-Base PPO 的 NQ/Hotpot = 0.480/0.433。**我们 flat_t5 已在其两集之上（0.491/0.463），但两集平均 vs 七集平均不可直接对比**——"吊打 3B"需等七集与贪心协议落地。
