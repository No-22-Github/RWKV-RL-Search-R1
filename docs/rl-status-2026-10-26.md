# Search-R1 RL 状态报告

日期：2026-10-26 ｜ 覆盖：SFT 基线 → RL v1 → RL v2（已完成）→ v3b（进行中）

## TL;DR

- **v2 成功且过线**：held-out EM@1 0.339 → **0.380**（+4.1 点，超过成功线 +0.04，配对分析约 3.4σ），pass@8 0.42→0.475，宽松 pass@8 0.485→0.505。提升全部来自 150–200 步的「行为期」，本质是把「多检索再作答」的用法练进策略，在全新题上可泛化。
- **v2 最佳检查点是 step-200**：续训到 250 步 held-out 零长进（EM 持平、次级指标全略降），旧题池边际已尽，据此停训换池。
- **v3b 正在跑**：从 v2-s200 完整检查点 resume，换上多跳偏好难题池（s250 策略重筛 4800 题 + 修复 id 撞号污染）。开局 16 步验证修复生效、与预期一致，200 步预计约 12 小时。核心验证点：**行为期能否从 v2 的 ~160 步提前到 100 步内出现**。

## 评测口径

- held-out：200 题（NQ 100 + HotpotQA 100，与训练题池不重叠）× 8 采样，T0.3 / top_p 0.5 / max_turns 4 / topk 3。
- **EM@1**＝单次严格匹配答对率（对应训练日志的 acc）；**pass@8**＝8 次里至少一次严格对；**宽松 pass@8**＝8 次里至少一次包含正确答案（多样性观察项）。评测噪声约 ±0.02（配对分析更小）。
- 训练侧指标（16 题 × 8 轨迹/步 = 128 条）：`acc`＝128 条轨迹答对率；`mixed`＝组内有对有错的题数（＝该步有非零优势/梯度的题数，全对全错优势为 0）；`avg_search`＝每条轨迹平均检索次数。

## v1：学会格式，提升太轻

- 配置：SFT adapter 直接开 GRPO，8 题 × 8 轨迹/步，**未筛题**（每步常常只有 2–4 组有非零梯度），约 100 步。
- 收获：格式收尾 0.774→0.983（未收尾 361→28 条），EM +2.0。
- 代价：采样多样性受损（宽松 pass@8 0.535→0.485）。
- 结论：有效梯度信号密度太低，提升被噪声淹没 → v2 的三个针对性改动全部由此而来。

## v2：筛题 + 两段式学习，s200 反转

**方案**（针对 v1 教训）：

1. **先筛题再训练**：用 step-100 策略 T1.0×8 采样，只留组内有对有错的 mixed 题（GRPO 才有非零优势）。实际 mixed 33.5%，自动扩筛到 4800 题，池约 1600；
2. **16 题 × 8 = 128 轨迹/步**（v1 是 8 题），lr 2e-6，奖励 = 对 1 / 错但格式对 0.3×F1 / 无效 −0.2；
3. **新增 `--f1_weight 0.3`**：F1 细化组内排序（接近正确 > 乱答），弥补纯 EM 太稀疏。

**训练动态（题池 acc，20 步滑动）**：0.49 → 40 步起爬升 → 0.60 → 120–150 步平台 0.61–0.62 → **180–199 行为期突破 0.649**。题池总增益 +12 点，held-out 增益 +4.1 点（差额 = 背题成分）。

**两段式（本轮最重要的发现）**：

- **0–150 步＝背题/削���期**：模型先摘低垂果实——背题池答案、强化占优行为。此段 held-out 持平甚至 pass@8 反跌（s100 0.352 / s150 0.340，pass@8 0.38/0.405 均低于起点 0.42）。s100/s150 时曾据此差点定论「瓶颈是 SFT 知识天花板」。
- **150–200 步＝行为期**：便宜奖励耗尽后，组内残余梯度集中在「查一次就答会错」的题上，唯一持续被奖励的行为只剩「再查一轮」→ 选择压力全指向多检索。题池 avg_search 1.87→2.25，s200 评测全指标跳升，配对 vs s100 净解锁 11 道原全错题、解锁 25/丢 14。**不是涌现，是自动形成的课程学习**（易行为先学、昂贵行为后学）。
- **续训 200→250 零长进**：EM 持平 0.380，pass@8 0.475→0.44、宽松 0.505→0.495、检索 2.56→2.37、配对解锁 13/丢 20。题池侧 acc 虽涨到 0.68，但那是第三遍重访的背题通胀 → **s200 即峰**，提前停训换池。

**v2 定性**：有长进且过线，但全在**行为层（检索用法）**、不在**知识层**——105/200 题 8 次仍全错，宽松 0.505 未回 SFT 的 0.535。RL 教会的是「怎么用检索」，没有教出新知识。

## v3 / v3b：换池重训，验证「提前开智」

**动机与核心假设**：旧池三遍已练透（题池 pass@8 0.93 是背题数字，held-out 真实值 0.475）；把题池偏向「单查答不对、多跳才可能对」的题（avg_search ≥ 1.4 的 mixed），行为期应能从 v2 的 ~160 步**提前到 100 步内**。

**做法**：s250 策略全新筛题（seed 888 / n 4800 / batch 32）→ 建多跳偏好池 `filtered-biased2.parquet`（约 1450 题）→ 从 **v2-s200 完整检查点** resume（s250 与 s200 在 held-out 上统计等价，筛题标签错位无碍；s200 次级指标更优故选它）。超参不变：lr 2e-6、f1_weight 0.3、16 题 × 8。

**筛题结果的独立泛化证据**（全新随机题，与训练池/评测集均不重叠）：与 step-100 策略筛题相比，全对 15.9%→25.8%、全错 50.6%→41.5%、mixed ~33% 持平——v2 的行为改变在题源分布层面真实存在，非评测集特异性。

**途中踩的两个坑（已定论、已修复）**：

1. **上游 checkpoint config 污染（rwkv_lightning_cuda `b79aca6`）**：jsoncpp 读取不存在键时会以 null 插入，长命进程写的第 2 个及以后的 checkpoint 带 `"seed": null, "planned_steps": null`，冷启动 resume 的字符串比对永不相等（v2 服务端一个进程连写 5 个 checkpoint，step-200 是第 4 个，中招）。修法：`sed -i '/"planned_steps" : null,/d; /"seed" : null,/d' <checkpoint目录>/training/checkpoint.json`。**v3b 中途要 restart 的话，resume 前对目标 checkpoint 跑同款 sed**。已建议回报上游。
2. **train.parquet id 撞号**：nq/hotpotqa 间同一 id 两数据集各一行（94% 池内 id 撞号），**唯一键是 (id, data_source)**。旧筛题按 id 记录 → 标签 last-write-wins 互覆盖；建池按 id 捞行 → 大量从未测过难度的「搭车题」混入，把 v3 首池 mixed 稀释到 5–8/16（v2 的池同样被污染，但流程对池噪声鲁棒，照样练出了结果）。修复：按 (id, source) 精确匹配重建池；`scripts/filter_questions.py` 已改为按 (qid, source) 记录/续跑/建池，根治。

## 下一步

1. **v3b 跑满 200 步**（约 12h）；题池侧观察行为期信号是否在 100 步前出现（参照 v2 的签名：acc 破平台 + avg_search 温和爬升 + 未收尾钉 0）。
2. **v3b 的 s100 / s200 adapter 出来后 scp 评 held-out**，基线 = v2-s200 的 EM@1 0.380。
3. 分支：**明显超过 0.38** → filter→train 迭代循环成立（用新策略重筛题、练熟的题自动退场、题池整体刷新），可继续滚雪球或延长步数；**持平** → 「提前开智」假设证伪，转下一档手段（e5 检索、扩蒸馏、对「检索 ≥2 次后答对」加奖励塑形）。
4. 运行期注意：筛题与训练不可并行（筛题钉策略版本，训练每步 publish 会 retire 旧版本导致 409）；服务端中途 restart 前对目标 checkpoint 跑 null 键 sed。

## 跨轮经验（复用清单）

1. **别在 200 步内评判 RL**：RL 有「先背题后改行为」的两段式，下结论要等完整曲线——用 s100/s150 就定论会把 v2 错杀成「瓶颈在 SFT 天花板」。
2. **题池涨 ≠ 泛化**：v2 题池 +12 点、held-out 只 +4.1；裁决只认 held-out。题池涨而 held-out 平 = 过拟合题池，早停的 adapter 可能更值钱。
3. **mixed 下降是成功信号**（题被练会毕业、退出 mixed），**acc 平 + mixed 平**才是真的没在学；`avg_search` 温和升是健康，但若奔 3.5+（max_turns=4 天花板）且未收尾抬头 = 查过头，提前停。
4. 每步题数是训练动态的选择，不为 GPU 利用率妥协；筛题可以 `--batch_questions 32` 提速，训练保持 16 题 × 8。
5. 数据坑：train.parquet 唯一键是 (id, data_source)，任何按裸 id 的去重/记录/建池都会被搭车题稀释。
6. 上游坑：长命进程第 2+ 个 checkpoint 无法被冷启动 resume（jsoncpp null 键污染 config），先 sed 再 resume。
