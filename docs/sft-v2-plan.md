# SFT v2 规划

日期：2026-10-27 ｜ 目标：重做 SFT 数据 → 基础模型重新 SFT → RL 约 200 步 → 榜单协议七集平均超过 0.431（7B Base PPO），8 集平均超过 ReSeek-7B 37.74

## 一、决定：从基础模型重新走一遍（不在 s300 上叠 SFT）

理由：

1. **在 RL 权重上再 SFT 会把 RL 学到的东西冲掉一部分**，结果很难解释：分数涨了不知道是数据好还是 RL 残留，跌了也不知道是哪一步。
2. **重走成本可控**：链路评测里 RL 真正的收益只有 v2 那 200 步（+5.8），v3b/v4 都是零。SFT（几十分钟）+ 200 步 RL 就能复现整条链。
3. **提交时方法干净**：一条 SFT → GRPO 的链，配置和数据都能一句话说清。
4. **有闸门**：SFT v2 单独评一次，七集平均 ≥ 0.35（v1 是 0.318）才进 RL；不到就回头改数据，不浪费 RL 时间。

备选（只在闸门没过、又想抢时间时用）：拿同一份 v2 数据在 s300 上小 lr 训 1 epoch，作对照。

## 二、v1 数据的问题（为什么要重做）

| 问题 | v1 | 影响 |
|---|---|---|
| 检索器 | 本地 BM25 | 训练和评测（e5 top-3）看到的文档分布不同 |
| 检索次数上限 | 3 次检索 + 1 轮只答，训练集里 0 条 4 次检索 | 榜单允许 4 次；MuSiQue 这类多跳题学不到"多查一次" |
| 检索结果截断 | 不截 | 榜单每次截 500 token |
| 数据量 | 2000 题留 843 条（教师 EM 0.467） | 偏少，SFT 后还有 24% 不收尾 |
| 思考风格 | 教师原始推理：Markdown 列表、平均 500+ 字符，还会在看到结果前"预演"检索结果 | 2.9B 学会编造、浪费 token；上游 500 token/轮的口径下容易截断 |
| 答案形式 | 只留 EM 对的 | 教师答对但多写了一截（"1962 FIFA World Cup" vs "1962"）全丢了 |

s300 榜单评测的错误归因（1925 题）：答对 40.1%，**没检索到 32.6%**（MuSiQue 60%），**检索到了但答错 19.4%**（NQ 26%），**答案形式不对 7.8%**（NQ 11%、Bamboogle 14%）。新数据主要冲后三类。

## 三、教师可用性（今天实测）

- 接口：Command Code `$API_BASE`，OpenAI 兼容 `/chat/completions`，模型 `Qwen/Qwen3.7-Flash`；思考在 `message.reasoning` 字段（脚本已兼容），`chat_template_kwargs.enable_thinking` 可开关。新 key 可用。
- 检索：本机直连 Pro6000 的 e5（`$RETRIEVER_URL/retrieve`），需要设 `NO_PROXY=$TRAIN_HOST`。
- **试点**（`outputs/distill/v2_pilot`，NQ/HotpotQA 各 50，榜单协议环境）：

| | 教师 EM | 宽松（包含） | 答对的检索次数分布 |
|---|---|---|---|
| NQ | 0.542 | 0.667 | 1 次 23 / 2 次 2 / 3 次 1 |
| HotpotQA | 0.532 | 0.574 | 1 次 9 / 2 次 7 / 3 次 4 / **4 次 5** |
| 合计 | 0.537（v1 BM25 是 0.467） | 0.621 | |

  上表是 95 题时的统计；100 题全部完成后：教师 EM 0.531，过滤后保留 47 条（原过滤规则），失败有不收尾 6%、动作格式错 3%、接口 HTTP 400 2%（v1 也有，0.3%）。吞吐约 100 题 / 6 分钟（32 并发），但长尾几条要多等几分钟。
- **思考改写试点**（`scripts/rewrite_think.py`，教师关思考模式改写）：平均 509 → 297 字符，纯文本 2–4 句，只引用已看到的检索结果，结论和动作一致。

结论：Qwen3.7-Flash 能当教师，e5 环境下比 v1 好 7 个点，还能产出 4 次检索的多跳轨迹。

## 四、数据管线

```
distill_teacher.py（榜单协议环境，首轮）
  → 失败题重采一次（T 0.7）
  → 答案对齐（可选）
  → strip_leak.py（整句删掉复述教师指令的句子）
  → 过滤（保留原始思考：长度 ≤ 800 token） → pack_sft.py → MiSS 训练包
```

### 4.1 生成（已改好 `scripts/distill_teacher.py`，新增 `--max_obs_tokens`）

```bash
set -a; source .env; set +a   # API_BASE、API_KEY、RETRIEVER_URL、TRAIN_HOST 等，见 .env.example
export NO_PROXY=$TRAIN_HOST
uv run python scripts/distill_teacher.py --n_per_source 4000 --seed 202 --teacher_suffix \
  --max_steps 5 --topk 3 --max_obs_tokens 500 --retriever $RETRIEVER_URL \
  --parallel 64 --out outputs/distill/v2
```

- 环境和评测逐字节一致：e5 top-3、每次截 500 token、4 次检索 + 第 5 轮带收尾提示只答。
- 题目：NQ / HotpotQA 训练集各 4000（共 8000，约 8 小时 @32 并发，64 并发若不限流约 4 小时）。和 v1 的 2000 题去重。
- **失败题重采**：首轮答错/不收尾的题用 T 0.7 再做一次，专门捞难题（多跳、需要改写检索词）的正确轨迹。需要给脚本加 `--qids_from` 只跑指定题。

### 4.2 答案对齐（新，需要写）

教师答案"包含"标准答案、但不 EM 时（试点约 8%），把 `<answer>` 换成最短的那个标准答案，例如 "Bennelong Point, Sydney, New South Wales" → "Sydney, New South Wales"。注意：思考是原始的，最后一步思考里可能写的是长答案，和对齐后的 `<answer>` 略有出入，可以接受。只对齐长度 ≤ 原答案、且标准答案是原答案子串的情况，避免硬改语义。

### 4.3 思考：保留教师原始思考，不改写（2026-10-27 用户决定）

统计（答对且有检索的轨迹，RWKV 分词器计 token）：

| | v1（932 条 / 2682 步） | v2 试点（52 条 / 140 步） |
|---|---|---|
| 每步思考 p50 / p90 / p95 | 124 / 445 / 654 | 136 / 479 / 882 |
| 每步都 ≤ 400 token 的轨迹 | 72.9% | 76.9% |
| 每步都 ≤ 800 token 的轨迹 | 91.0% | 90.4% |
| 含 Markdown 列表的步 | 38.6% | 47.9% |
| 明确复述教师专属附加指令的步 | 8.2% | 5.7% |

- 原始思考不长，用长度过滤就够：**每步 ≤ 800 token**，丢约 10% 的轨迹。如果要补跑上游 500 token/轮的版本，改成 ≤ 450。
- "第一步预演检索结果"抽查下来多半是"计划怎么看结果"，不是编造，不处理。Markdown 列表保留（`clean_txt` 已去空行）。
- **要处理的是指令泄漏**：思考里复述 "always run at least one search" 之类只给教师看的话，学生的 prompt 里没有这句。只算教师独有内容（学生 prompt 里也有的 "short entity or phrase" 不算），答对轨迹里 17–22% 含泄漏。
  - 在提示词里要求"思考里不要提这些说明"**没用**：同 100 题对照（`outputs/distill/v2_pilot_quiet`，`--quiet_suffix`），复述的步 6.4% → 7.3%，EM 0.531 → 0.525。
  - 让 LLM "只删泄漏句"也不行：它总会顺手改别的字，纯删除校验大多不过。
  - **采用 `scripts/strip_leak.py`**：按句切分、整句删除含教师独有内容的句子，其余原文不动，不调 API。v1 答对轨迹 233 步删成功、2 步失败（失败的整条丢）。
- `scripts/rewrite_think.py` 留作备用，默认不用。

### 4.4 过滤与配比

- 保留：EM 对（含对齐后）、≥1 次检索、每步思考 ≤ 800 token、删句失败的丢掉、无完全相同的重复检索。
- 配比目标：总量 **3500–4500 条**（v1 的 4–5 倍）；按检索次数大致 1 次 40% / 2 次 30% / 3–4 次 30%，NQ 里大量"一次就答对"的题下采样，HotpotQA 的 3–4 次全留。
- 验证集 100 条。
- **SFT 用过的题从 RL 题池里排除**（RL 筛题时按 (id, source) 去重）。

## 五、训练

- 机器：$SFT_HOST `~/no22/rwkv_lighting_cuda`，脚本照 `scripts/train-miss-sr1-v1.sh` 复制一份 v2。
- 起点：基础模型 rwkv7-g1k-2.9b-20260930-ctx25600（sha256 前缀 d8f8ecd4）。
- 网格：MiSS r16，lr {3e-5, 5e-5}，2 epoch，存每 0.5 epoch 的检查点（数据量大了，1 epoch 可能就够）。
- 评测：全部按榜单协议（`docs/rl-status-2026-10-27-pm.md` 里的命令），对比 v1 SFT 的 0.318；同时看 format_ok、不收尾率、平均检索次数。

## 六、之后的 RL

- 起点：SFT v2 最好的一档（过闸门 ≥ 0.35）。
- 环境：直接用 v5 的设置（`chain_v5.sh`：top-3、截 500、`--max_turns 5`），先重筛题池（排除 SFT 用过的题）。
- 200 步，每 50 步按榜单协议评一次；参照 v2 那 200 步拿到 +5.8 的经验，如果 SFT v2 能到 0.36–0.37，RL 后有希望到 0.42–0.43。

## 八、风险

- **Command Code 限流 / 计费**：试点 32 并发没遇到 429；全量前先用 64 并发跑 200 题看看。
- **答案对齐过拟合标注习惯**：NQ 的标准答案本身噪声大，对齐只做子串收缩，不做改写。
- **教师自身知识泄漏**：教师常常"其实知道答案"再象征性查一次；原始思考里会写出来，靠"至少检索一次"的过滤兜底。

## 九、实际执行（2026-10-27 晚，覆盖上面第四节的题量设计）

用户拍板：不做 8000 题，v1 的题和新筛的难题合并到 **2000 题，全部在 e5 榜单协议环境下重跑**（v1 的 BM25 轨迹不再复用）。

1. **筛题**：候选 `data/sft/candidates-v2-4000.parquet`（NQ/HotpotQA 各 2000，排除了 RL 筛过的 7126 题和蒸馏/试点用过的题）。s300 按榜单协议做一遍（`outputs/sft-select/s300-cand4000`）：NQ EM 0.396、HotpotQA 0.525。
2. **题单** `data/sft/teacher-v2-2000.parquet`（列 `bucket` 标来源）：

   | bucket | NQ | HotpotQA | 说明 |
   |---|---|---|---|
   | v1 | 345 | 516 | v1 训练包（train 821 + val 40）的题，随机题、教师在 BM25 下能做对 |
   | wrong | 312 | 500 | s300 答错（NQ 从 450 随机删到 312 凑 2000） |
   | hard_ok | 43 | 184 | s300 答对但检索 ≥3 次，全部 |
   | easy | 50 | 50 | s300 1–2 次检索答对 |

   题目层面普通题（v1 + easy）约 48%；难题留存率低，最终轨迹里普通题预计约 6 成，兼顾基础模型先学基本套路。
3. **蒸馏**：`outputs/distill/v2`（日志 `outputs/distill/v2.log`），16 并发，开局约 0.8 题/秒。
4. 之后：`strip_leak.py` → 按每步 ≤800 token 过滤 → 答案对齐 → 打包。这 4000 道候选题 + v1 题全部从 RL 题池排除。
